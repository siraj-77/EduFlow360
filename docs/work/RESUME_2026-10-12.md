## The four lessons worth carrying (each cost real time)

1. **A green gate run BEFORE the commit proves nothing about the commit.**
   PR #12's four console-guard e2e cases ran green against the working tree,
   were staged with `git add apps/web/src …` — which does **not** cover
   `apps/web/tests/` — and were never in the squashed commit; the post-merge
   `git reset --hard` then discarded the last copy. **What caught it: the test
   COUNT (37 where 41 had passed).** What did not catch it: every gate. **Always
   verify `git diff --cached --name-only` against the intended file list before
   committing, and treat a count regression as a data-loss signal.**
2. **A teeth-proof is not optional — mine caught my own vacuous test.** The
   first value oracle checked `Object.keys(map).length === 0` on a **Map**
   (always zero), so every row `continue`d and all three template tests passed
   against nothing. Only the deliberate value break exposed it. The fixed
   oracle then revealed a real `rgba` formatting drift and **a recurrence of
   the comment-parsing bug** below. Break it on purpose, every time.
3. **Strip comments before any declaration parse — twice today.**
   `apps/api/prisma/read-declaration.mjs` counted brackets and strings but not
   comments, so `AC-2's` (an apostrophe in a comment) swallowed the seed
   array's closing bracket; and the ui-kit's `--warn` comment contains the
   literal `--warn: #d97706`, so a `--name: value;` scan swallowed the comment
   body. Both parsers are now comment-aware. If you write a third, start there.
4. **gitleaks flags a `sha256` of a PUBLIC tracked file as `generic-api`.**
   `template-checksums.json` tripped the `Secret scan` on PR #13's first run;
   resolved with a documented path allowlist in `.gitleaks.toml` (the file
   exempted, nothing else), following the `.env.example` entry already there.
