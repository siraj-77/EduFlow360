## The one thing to know: `npm run dev` works now, and why it didn't

Running the project the documented way surfaced a real bug (now fixed
in PR #4): `loadEnvFiles` deleted every key `.env` introduced before
loading `.env.local`, so a partial `.env.local` silently wiped
`SCHOOL_ID` and the API refused to boot. **The local developer
environment needs three things that are now documented:**

1. `SCHOOL_ID` — in `.env.example` with the seed's default
   (`00000000-0000-4000-8000-000000000001`).
2. `JWT_ACCESS_SECRET` / `JWT_REFRESH_SECRET` — `openssl rand
   -base64 32` each; the local `.env` now carries them.
3. A **bootstrap administrator** — see "The login path" below.

## The login path (there are no stored credentials; this is by design)

The local database ships with **no accounts**. The seed creates a
`SCHOOL_ADMIN` bootstrap account **password-less** (`PLT-107`'s invited
state), and no route or script issues a setup token locally — in
production it is an out-of-band operational step. **Verified end-to-end
this session** (all nine steps PASS against the running dev servers):

```
SEED_ADMIN_EMAIL=admin@school.lk node prisma/seed.mjs    # creates admin, INVITED
# mint the setup token the way PrismaSetupTokenRepository.issue does:
#   sha256(plaintext) → user.setupTokenHash, +1h → user.setupTokenExpiresAt
POST /auth/setup/complete  { token, password }      → 200  (ACTIVE + hash)
POST /auth/login          { identifier, password }  → 200  + eduflow_session
GET  /permissions/me      with the cookie           → 200  (SCHOOL_ADMIN grants)
GET  /permissions/me      without a cookie          → 401
POST /auth/sign-out       with the cookie           → 200  + cleared cookie
GET  /permissions/me      with the OLD cookie       → 401
audit trail: SETUP_COMPLETE → LOGIN → SIGN_OUT
```

`SCHOOL_ADMIN` **is** the super-admin here: `AGENTS.md` §2.1 forbids a
cross-tenant role, so the in-school administrator is the ceiling.

Web routes verified 200 across locales: `/en`, `/en/sign-in`,
`/en/sign-in/forgot`, `/en/sign-in/reset?token=…`, `/si/sign-in`,
`/ar/sign-in` (RTL), `/ta/sign-in`.

**Open gap worth a ticket:** there is no local tooling for step 2 of
the login path. A `dev:setup-token` script (or seed support for
`SEED_ADMIN_PASSWORD`) would make the local sign-in reachable without
hand-minting a token — the owner has not yet ruled on which shape.
