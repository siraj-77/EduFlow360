### The one design decision worth knowing before you touch this code

**`AuthAlert` is the single carrier of the template's `.alert` slot**, consumed by four alert sites: `sign-in-form.tsx` (the 401/429 message, with `tabIndex={-1}` and the focus ref), `forgot-password-form.tsx`, `reset-password-form.tsx` (three sites), and `sign-in-social-grid.tsx`. Its spec derives every value from the template's **own CSS at test time** — `padding:10px 12px` → `py-2.5 px-3`, `border-radius:9px` → `rounded-control` (asserted equal to the kit's light `--radius-control`), `font-size:13px` → `text-[13px]`, `rgba(…,.12)` → `/12`, `rgba(…,.3)` → `/30`. **If you add a fifth alert, use `AuthAlert`.** A hand-written class list will now fail `sign-in-social-grid.spec.tsx`, and a change to the template's `.alert` rule will fail `auth-alert.spec.tsx`.

### Three defects found and fixed in my own new code, recorded because each cost a cycle

1. `tokenValue` returned the **second** occurrence of a token rather than the requested one, because the match was taken from an `exec` after the loop instead of from inside it. "The kit's light `--radius-control`" silently became the dark `8px`, so a correct component looked wrong.
2. `spacingUtility` treated 10px as off-scale and emitted `py-[10px]` instead of `py-2.5`. Tailwind ships a named step at every **half** unit; the test is now `Number.isInteger(units * 2)`.
3. Several class assertions queried `getByTestId` without rendering anything first. The RED was real for the right reason (module missing), but the spec would have failed again immediately after GREEN.

Plus two environment traps the repository had already documented, which I hit anyway and had to re-derive: a `new URL(…, import.meta.url)` **literal** is rewritten by Vite into an asset reference and then resolves to a non-`file:` scheme under jsdom (`session-cookie-name.spec.ts:22-26`, `format-gate.spec.ts:12-19`), and a directory `URL` built without a **trailing slash** replaces its last segment when a child is joined onto it, so `credential-field.tsx` was read as `…/auth/credential-field.tsx` and died with `ENOENT`.

## 5. ⚠️ Read this before you trust anything else in the repo about `API-101`

**`API-101` was raised this session with a wrong root cause and corrected the same day.** If you find an entry saying _"the seed has gained a password"_ or _"the seed regressed"_, it is superseded by `d73fef8` and `bb270b4`, and by the corrected entry in `docs/work/TODO.md`.

**The wrong claim:** one integration case failed locally — `apps/api/src/config/database-contract.integration.spec.ts:536`, "no account in the seed's school carries a password" — and I attributed it to a seed regression, supported by a check that reproduced the failure on `efd10c7`.

**Why that was not enough:** reproducing a failure on an unchanged tree proves it did not come from _that branch_, not that I knew _what caused it_. CI then ran the identical gate on a **fresh database** and **passed** (run `38591701150`), which directly contradicted the seed-regression story.

**The real cause, measured with `psql` against the local server, not inferred:**

- `.env` and `.env.local` both name **`eduflow360db`, which has no tables at all** — `relation "User" does not exist`, `relation "School" does not exist`.
- The schema EduFlow360 actually migrated lives in **`eduflowdb`**, which `RESUME_2026-09-30.md:127` records as _"untouched — holds the legacy 60/46-table multi-tenant schema"_.
- `eduflowdb` carries residue: schools `[E2E] Alpha Academy`, `[E2E] Beta Institute`, `MMPS001`, and three user cohorts in which **every** account has a `passwordHash` (8, 6 and 3), under CUID-style school ids no longer present in `School`.
- The redirect mechanism: `apps/api/vitest.integration.config.ts` **prefers an already-set `DATABASE_URL`** over the `.env` it loads, so a hand-exported value redirects every integration file. Correct by design (a CI-injected value must win) and invisible in the config.

**Left as an open ticket, not fixed:** repointing the suite drops whatever `eduflowdb` holds, and `AGENTS.md` §11 wants a missing thing named rather than a default chosen. **The next session should decide which local database the integration gate should point at.**

## 6. Two findings worth carrying forward

**A fourth copy of the alert had already forked.** `sign-in-social-grid.tsx` carried a hand-written class list while the other three alert sites moved to `AuthAlert`. The exact bypass the component exists to prevent, already happened inside one feature, within one day. It is now the fourth consumer and the spec names the forbidden spellings (`bg-danger/5`, `text-sm`, `font-medium`) so review is not the only guard. **The general lesson: when you introduce a shared component, grep for the pattern it replaces in the same change, not in a later one.**

**The e2e flake had a real cause, and retries were the wrong tool.** AC-3's test failed with `dir` reading `null` while a direct fetch of the same route returned `dir="ltr"`. Mechanism, read from the dev-server log: two parallel workers raced the single dev server, `SyntaxError: Unexpected end of JSON input` truncated an RSC payload, Fast Refresh reloaded, `<html>` was recreated. `retries: 2` was already set and **did not help** — a retry runs against the now-warm server and passes, which is how a flake goes invisible instead of fixed. Fixed with `workers: 1` + `fullyParallel: false`, the same remedy `SEC-112` chose for `vitest.integration.config.ts`. Cost measured: **1.2m → 1.8m**.
