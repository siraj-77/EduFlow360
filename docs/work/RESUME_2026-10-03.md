## 2. ⚠️ OPEN DEFECT — the flaky integration gate

**Reproduced twice, about 1 run in 8:**

```
expected { action: 'reject-unclaimed' } to deeply equal { action: 'reject-consumed' }
apps/api/src/modules/auth/infrastructure/postgres/prisma-setup-token-repository.integration.spec.ts
```

After exactly one caller wins the setup-token race, the losers are told "too late".
Receiving `reject-unclaimed` means `deploymentState()` classified the deployment as
`bootstrap-claimed`, which requires **no** `INVITED` user with a null `passwordHash`
to exist at that moment.

**Ruled out:** there is no `deleteMany` and no `TRUNCATE` in any spec, and each
integration file mints its own `schoolId` via `randomUUID()`, so no two files share
a school.

**Strong hypothesis, unconfirmed.** This is the ambiguity recorded when the token
core was written: `PLT-107` option (b) NULLs the token columns, so _consumed_ and
_never issued_ are indistinguishable from the token alone, and the code reads the
**account** to disambiguate. `PLT-104`'s OTP invites will create a second
no-credential `INVITED` row, which is the documented way this breaks. Something is
producing that state intermittently under parallel file execution.

**Fix this before trusting the setup path.** A flaky gate is worse than a red one:
a red gate stops work, a flaky one teaches re-running until green.

Measured against a stashed clean `HEAD`:

```
ERROR: Coverage for lines (89.72%) does not meet "src/**/domain/**/*.ts" threshold (90%)
```

This predates all of the work in this session. I briefed several subagents that
`test:coverage` was red only on two `apps/web` zero-file tiers — that was wrong, and
it was repeated without checking. The subagent measured instead of trusting the

**Cause is mechanical.** Adding `unplugin-swc` changed how type-only modules compile:
SWC emits `export { };` — a real statement — where esbuild emitted nothing. v8 then
reports `0/0` for those files. Every domain file **with** executable code is at 100%.

So the honest reading: **the tier is measuring pure interface files as though they
were uncovered code.** It is a reporting artifact, not a coverage regression.

**Do not lower the threshold.** `scripts/check-coverage-tiers.mjs` forbids it in its
own output, and it is right. The fix is a decision about what the tier means.

**Also red, and correctly so:** two `apps/web` hooks tiers matching zero files. I
recommended deleting them; that was wrong. A zero-file tier is a promise about code
not yet written. Deleting it removes the ratchet and buys green with no engineering
in it.

## 5. Next work: the last auth route

**`GET /auth/oidc/callback`, in BOTH link and sign-in modes.**

This closes the must-link chain (`SSOT.md` D57). The reasoning, because it is not
obvious and getting it wrong produces a system where nobody can log in:

1. `POST /auth/setup/complete` creates the first administrator (done)
2. `POST /auth/login` gives them a session — **the only way anyone gets one** (done)
3. The callback in **link mode** attaches a Google identity to that account (next)
4. The same callback in **sign-in mode** lets everyone else in

Must-link means Google **never auto-provisions a `User`**. That is deliberate: the
domain allowlist is a _pre-filter_, not authorisation, and auto-creating a user for
any verified `@school.lk` Google account would let **any student with a school Gmail
become a system user.**

Consequences to carry into that route:

- `@Public('<reason>')` plus a new `route-guards.allowlist.json` entry
- `@Audited(...)` — the audit record belongs here, not on the redirect, because this
  is where a stranger's assertion becomes a local account
- the signed state cookie must be **opened**, not trusted; a correct signature over a
  malformed payload must fail closed
- rate limiting, as on `setup/complete`

## 6. The four traps that cost real time this session

1. **Never edit files with PowerShell string cmdlets.** They corrupt UTF-8, and
   **backticks in comments silently become newlines and tabs**. This happened three
   times, including to me, and each time it broke a file mid-task. Use Node's `fs`
   from a _script file_, or the Edit tool. Never `node -e` with nested quotes.
   Apostrophes inside single-quoted PowerShell strings break them too.
2. **A glob written `star star slash` ends a block comment early.** Two files were
   corrupted by it before this session. Describe paths in words.
3. **Never `import type` a constructor dependency in `apps/api`.** It breaks
   `emitDecoratorMetadata`, Nest cannot resolve the token, and **the whole app
   fails to boot** — and `tsc` does not complain, `lint` _demands_ it, and the build
   goes green. Use `@Inject(Token)` explicitly, as
   `auth/controllers/oidc-sign-in.controller.ts` now does.
4. **`pnpm add` on pnpm 11 writes a literal placeholder** `pkg: set this to true or
false` into `pnpm-workspace.yaml`, which breaks **every** gate because the repo
   runs `pnpm install` before each script. Set it to `true`.

## 7. How this session's work went, and what to keep

**Delegating to subagents worked, and monitoring them was the valuable part.** Two
subagents found production defects I had not looked for: the app being unable to
boot, and a missing `inject` that made every request fail. Both were invisible to
nine green gates.

**Verify independently, always.** Every claim below was checked against real output
before it was recorded, and several subagent reports were wrong or incomplete:

- one reported `format:check` red; a second reported it green; **I believed the
  second without isolating which was true**, and it was a lockfile formatting
  difference the second agent happened to fix
- one reported integration "transient and unexplained" — it was neither
- one claimed coverage was pre-existing red, which **turned out to be true**, and
  which I had been mis-briefing agents about

**Prefer mutation over assertion.** A test never observed failing is not evidence.
Concretely, this session: the naive read-then-write was reinstated to prove the
concurrency test fails (5/5 red); the suffix-domain rule was reinstated (5 failures);
"empty list permits everyone" was reinstated (12 unit + 6 integration failures); the
multi-line decorator parser was reverted to prove its test red; the setup
transaction was removed to prove the atomicity test red; the cookie flags were
broken to prove the harness red; and the enumeration timing test was found to be
**unable to fail** and had to be rebuilt before it was worth anything.

**When a test asserts a defect, invert it rather than delete it.** Two
characterisation tests here asserted the app could not boot. Inverting them locks in
the fix; deleting them would let the defect return unnoticed.
